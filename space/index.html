What the engine refuses

Rules the booking engine enforces.

Each of these is a block, not a warning — verified by the prototype's own test suite. Rules were written from how the space is actually run.

Gate

A blocked slot cannot be booked

If an operator blocks a room for maintenance, the slot disappears from availability and any booking attempt against it is refused outright.

Hiding it from the calendar is not enough — the engine rejects the request as well.

Gate

Payment is confirmed by reading it back

When the gateway calls back, the engine re-reads the bill from the gateway's own API and matches the amount before marking the booking paid.

A forged or replayed callback does not mark anything paid.

Gate

Cancellation follows the policy window

A paid booking can be cancelled more than 24 hours ahead; inside the window the engine refuses and points the member to the operator.

Held bookings can always be released, so a cart abandoned mid-payment does not hold a seat all day.

Gate

Members see only their own bookings

A member signed in with their code sees their own bookings and receipts — never another member's, and never the operator's calendar.

Administration is a separate sign-in, not a role a member can reach.
